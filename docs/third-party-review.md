# Third-party distribution review

The historical evidence below records the previously inspected Windows bundle, not the contents of new packages. Refract's MIT license covers Refract; it does not replace third-party licenses.

## Current distribution decision

Refract release assets do not embed TinyTeX, TeX Live, or a replacement SyncTeX executable. Starting with 0.3.1-pre-release-2, the installer downloads checksum-verified upstream TinyTeX and SyncTeX directly into per-user application data and Refract discovers the complete managed toolchain automatically. `REFRACT_TEX_BIN` overrides this with an external installation. `setup-tex.ps1` remains a path-validation helper and performs no downloads or execution. There is no fallback to old bundled or vendor copies. Fresh setup requires internet access; subsequent compilation can work offline with installed packages. Codex and OpenCode CLIs remain optional external integrations.

Packaging uses an explicit application-file allowlist, no TeX `extraResources`, and before/after-pack hooks. The first rejects changes to the approved file boundary; the second scans the actual staged application for TeX trees, executables, and known archive names before installer generation. Both Windows packaging commands use these hooks, including direct electron-builder invocations with the checked-in configuration. Stale `vendor/TinyTeX`, source caches, and unrelated files under `build/` are outside the allowlist. These checks enforce this boundary; they are not a general third-party license scanner. A deliberate override of builder configuration/hooks requires its own review. Never redistribute an old `dist/` artifact as if rebuilt under this boundary.

This is a removal decision, **not a finding that corresponding source was recovered**. The ignored candidate archives and manifest below remain historical audit evidence, not an offer of complete corresponding source. `verify:tex-sources` remains a historical cache verification utility requiring the old pinned catalogue; the new setup does not provision that catalogue. A passing archive check is not permission to re-enable binary bundling.

## Authoritative basis

- [TinyTeX upstream licensing](https://github.com/rstudio/tinytex-releases#license) says it redistributes a subset of TeX Live and omits LaTeX package sources.
- [TeX Live copying conditions](https://github.com/TeX-Live/installer/blob/master/LICENSE.TL) require compliance with the individual packages' terms, whose own legal statements control.
- [GNU LGPL 2.1, section 6](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.html#SEC4) describes executable distribution conditions for library linking, including modification/relinking materials under the applicable option. Notices alone do not establish that the old apparently statically linked SyncTeX met those conditions.
- [Ghostscript upstream license](https://github.com/ArtifexSoftware/ghostpdl/blob/master/LICENSE) identifies AGPL-3.0-or-later coverage; [AGPL section 6](https://www.gnu.org/licenses/agpl-3.0.html#section6) addresses conveying non-source forms. A version-matched candidate alone does not establish corresponding source for a particular modified binary.

The practical conclusion from these sources and the unresolved build evidence is to stop conveying these binaries through Refract rather than assert a complete source offer.

## Owner action required before making the repository public

Merging this change does **not** remove the SyncTeX archive from Git history, tags, old branches, PR refs, clones, caches, or GitHub source archives of old commits. It does **not** cure obligations from installers already conveyed. This PR performs no history rewrite, tag deletion, release deletion, or publishing.

The owner must inventory all reachable refs and historical binary paths (including the removed SyncTeX archive), and choose an authorized pre-publication history cleanup or a new clean publication repository, or establish the required distribution materials for every retained binary. Coordinate ref/history cleanup with GitHub and existing clone holders; deleting the current file or moving a tag is insufficient. Verify the actual public refs and downloadable source archives afterward.

Read-only release inspection on 2026-11-16 found installer assets on `v0.2.2`, `v0.2.1`, `v0.2.0`, `v0.1.11` through `v0.1.5`, and unprefixed `0.1.4`, `0.1.3`, `0.1.2`, `0.1.1`, `0.1.0`. Before public visibility, review **every** release's assets and binary contents, including installers, blockmaps, checksums, and other downloadable copies. Remove/replace unverified distributions through a separately authorized owner operation, or supply verified required source/build/relinking materials and notices for retained binaries. Regenerate associated metadata for replacements. Do not assume the oldest installers have identical contents. New TeX-free packages do not retroactively repair older installers. Assess obligations to existing recipients separately; withdrawal does not extinguish them.

Repository publication remains blocked on that historical/release disposition. Other dependency and trust/security findings are outside this decision. Future releases must inspect newly built package contents and retain dependency notices; reintroducing TeX requires a new component-by-component review with verifiable sources, build inputs and any required relinking materials.

## Historical source audit (not a current distribution offer)

### Inspected components

- The unpacked Windows build includes Electron's `LICENSE.electron.txt` and `LICENSES.chromium.html`.
- The packaged npm dependencies identify their licenses as MIT, Apache-2.0, or (for DOMPurify) a choice of MPL-2.0 or Apache-2.0. Their license files are present in the packaged module directories. PDF.js also includes separate notices for character maps and fonts. The packaging configuration excludes PDF.js's optional Node-only `@napi-rs/canvas` packages; a rebuilt unpacked Windows app was checked to confirm they were absent, and its three packaged application tests passed, including PDF rendering and navigation. Earlier release assets may still contain these packages and need their own review before public distribution.
- The setup script downloads TinyTeX v2026.10 using a pinned SHA-256 and replaces its Windows SyncTeX executable. The packaged distribution retains `LICENSE.TL`, `LICENSE.CTAN`, and the added `SYNCTEX-NOTICE.txt`. The installed TeX Live package catalogue in the inspected unpacked build matched the one in the pinned TinyTeX archive by SHA-256 (`466f964737da319f36a140bfa3a82c578ea6a5b45c791a025c0a9e0d7c5e77da`).
- The baseline repository also contained the SyncTeX Windows binary independently of TinyTeX. The upstream Windows build configuration links Kpathsea and zlib; the executable's import table lists only Windows system DLLs and contains Kpathsea strings, indicating Kpathsea is likely statically linked. Its embedded strings identify zlib 1.3.2, the same version found in the candidate TeX Live source snapshot. Kpathsea is LGPL-2.1-or-later. Copies of upstream Kpathsea and zlib license texts are included alongside the binary and copied into the packaged TeX distribution. Matching a version string does not prove the exact build inputs, and any applicable source and relinking requirements for this binary still need verification; these notices alone do not establish compliance.
- That catalogue contains 322 records, including metadata and platform-specific records. Its license classifications include LPPL, GPL-family, font, and other licenses; 41 records have no catalogue license field, including Windows-specific binary records. Catalogue metadata is an inventory aid, not a substitute for each component's terms.

### Source audit status

The local audit now retains these source archives under the ignored `vendor/refract-tex-source-audit` directory: 167 package `.source.tar.xz` archives whose SHA-512 values match the pinned TeX Live catalogue, a 162,708,079-byte TeX Live source snapshot at commit `dc8efcd41054ec4bf7f96c022cd2d91fe346f6e1` (SVN revision 78081), GhostPDL 10.08.0 at commit `05631c2cba4e578fdd6bd25cae6f0939436de848`, and Biber 2.22 at commit `1e86e5e80f76b063a9e277c8e331424e2a318c57`. Their downloaded archive SHA-256 values are recorded below. These files improve the evidence available for a source release, but their presence does not by itself prove that every archive is the complete corresponding source for each binary in TinyTeX v2026.10.

For Ghostscript, the shipped `tlgs/README.TEXLIVE` identifies the bundled subset as Ghostscript 10.08.0 and states that its binaries were compiled with `--disable-compile-inits`; it also documents distribution-level removals and font/configuration changes. The locally retained GhostPDL 10.08.0 source archive is therefore version-matched, but the audit has not verified the exact source tree, patches, build inputs, or a reproducible Windows build for the bundled executable. The upstream Ghostscript release page provides both AGPL and commercial builds and a source download, but that fact alone does not prove the TeX Live binary's correspondence to that source.

For Biber, the installed TeX Live catalogue identifies version 2.22 and the retained source archive contains the upstream builder notes, which say the standalone executable is packed from Perl using PAR::Packer. The audit has not matched the exact Windows executable to its source commit, build script, packed Perl/modules, and licenses.

For SyncTeX, the replacement executable is the unmodified TeX Live `synctex.windows` revision 78097. The retained TeX Live source snapshot is revision 78081, after the recorded SyncTeX source fix at revision 78080 but before binary package revision 78097. The source review has not established whether relevant source, build configuration, Kpathsea, or zlib inputs changed between those revisions, nor recovered the exact Windows build invocation and relinking materials. The installed TinyTeX binaries also span package revisions newer than the retained source snapshot, so that snapshot cannot serve as a blanket corresponding-source archive for the whole distribution.

**Source correspondence review: unresolved.** The concrete remaining work is to map the installed Windows executables to their source revisions and build inputs; verify the complete sources and licenses (including static-link relinking materials where applicable); then assemble and inspect the source offer alongside the installer. This repository's local source cache is ignored and is not included in a release.

### Audit evidence and remaining details

TinyTeX's upstream documentation says its distribution does not bundle LaTeX package sources. On 2026-11-02, the 2026-10-01 TeX Live archive catalogue had matching source-archive SHA-512 checksums for all 167 source archives listed in the pinned TinyTeX catalogue. All 167 archives were downloaded and verified against those checksums into the ignored local `vendor/refract-tex-source-audit` directory; these archives are not part of this repository or a release. The checked names and hashes are recorded in [tex-source-manifest.json](tex-source-manifest.json), and the files were retrieved as `<name>.source.tar.xz` from `https://texlive.info/tlnet-archive/2026/10/01/tlnet/archive/`. The archive catalogue and TinyTeX catalogue differ for `texlive-scripts` and two installation/configuration records, so this comparison does not establish complete equivalence of the distributions.

For a retained historical pinned TinyTeX installation, run `npm run verify:tex-sources -- <archive-directory>` to check the manifest against the pinned TeX catalogue and verify every listed archive. This verifies package-source archive coverage and bytes only; it does not establish the binary source and relinking requirements below.

The inspected bundle also contains GPL-family executables, but the package-source archives alone do not establish the complete corresponding source used to build each executable, the availability period, or the notices required for every component. For example, `tlpkg/tlgs` identifies itself as a modified subset of Ghostscript 10.08.0 and contains the AGPL-3.0 license. Its `README.TEXLIVE` describes removed files, replaced fonts and a build flag. An upstream [Ghostscript 10.08.0 source tag](https://github.com/ArtifexSoftware/ghostpdl/tree/ghostpdl-10.08.0) exists, but this review did not establish whether that tag and the documented changes alone are the complete corresponding source for the shipped Windows binaries. The review still needs to identify exact corresponding sources and document applicable source and notice obligations. In particular, do not assume that a link to the latest upstream source corresponds to an older binary.

The upstream sources listed above remain candidates, not verified complete corresponding sources or a source-distribution offer. In particular, the Windows binary build instructions and any patches and relinkable materials remain unverified.

The TeX Live commit archive records a [SyncTeX source fix at revision 78080](https://tug.org/pipermail/tex-live-commits/2026-February/036686.html) and the [Windows SyncTeX binary update at revision 78097](https://tug.org/pipermail/tex-live-commits/2026-February/036703.html). The candidate revision 78081 falls between them, but that ordering does not prove which source tree and build environment produced the binary.

The archived `synctex.exe` has SHA-256 `ebec9830f4a357ae8853a4ae1716abd0b0c2e383e73091548caca94ec38f8ebb`; its PE header reports a build timestamp of 2026-02-23 22:38:40 UTC, shortly before the recorded Windows binary update. The binary has one PE debug record, but its build inputs have not been established. A PE timestamp is supporting evidence only and is not proof of the build inputs.

The locally retained GitHub source tarballs have SHA-256 hashes `4e2b69832ddcb882b83a90441b50df3b62e0f4fcbbb88307fd9030d2ee59d6f1` (TeX Live), `b43eb687506330d37ac553ce0d167fbef6beae715a729cb6148efb73bfc35504` (Ghostscript), and `25586e0a35059abaed988fa2b43dd13362d228ebc3f9df4fe71366d84c8df5ad` (Biber). These hashes identify the downloaded archives; they do not establish that those archives produced the bundled executables.

Useful upstream references: [TinyTeX releases and licensing](https://github.com/rstudio/tinytex-releases#license), [TeX Live redistribution guidance](https://github.com/TeX-Live/installer/blob/master/LICENSE.TL), and the [GNU license FAQ on corresponding source](https://www.gnu.org/licenses/gpl-faq.en.html#UnchangedJustBinary).

This assessment does not establish legal compliance or cover a later build whose dependency or TeX contents differ. Recheck it for each release.
